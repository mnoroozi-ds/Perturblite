# PerturbLite packet data

This directory stores the normalized packet-level CSV files consumed by the
surrogate classifier and adversarial generator. PCAP parsing is intentionally
separate from model training so packet extraction, labeling, and protocol
validation remain auditable.

## Source data

The experiments use raw packet captures from CIC-IDS2017 and CIC-IDS2018.
Equivalent PCAP collections can be used when they provide:

- complete packet bytes;
- reliable attack time windows and endpoint information; and
- enough benign and malicious packets for stratified splitting.

Use a packet parser such as Scapy or dpkt. Do not use aggregated flow features
from CICFlowMeter as model inputs: PerturbLite operates on packet bytes.

## 1. Parse and label packets

Parse header and TCP segment data from each PCAP. Associate packets with their
ground-truth activity using the following 6-tuple:

```text
(source IP, destination IP, source port, destination port, protocol, epoch time)
```

Assign `label=0` to benign packets and `label=1` to packets belonging to the
selected attack category. When one output file contains several categories,
also store a descriptive `attack_type` value such as `DoS`, `DDoS`, or
`Infiltration`.

## 2. Keep attacker-controlled traffic

Identify the source endpoint for each flow and retain only forward packets sent
by that endpoint. Backward packets are excluded because they are generated by
the remote endpoint and cannot be directly controlled by the adversary.

The current representation is defined for TCP packets. Keep TCP header and TCP
segment boundaries available during preprocessing; these boundaries determine
which final features are mutable.

## 3. Remove environment-specific and protocol-sensitive fields

Packets may initially contain up to 1,594 bytes. Remove the following fields
before generating model features:

| Protocol area | Removed information | Size |
|---|---|---:|
| Ethernet | Complete Ethernet header | 14 bytes |
| IP | Version | 1 byte |
| IP | Differentiated Services field | 1 byte |
| IP | Protocol identifier | 1 byte |
| IP | Source address | 4 bytes |
| IP | Destination address | 4 bytes |
| TCP | Source port | 2 bytes |
| TCP | Destination port | 2 bytes |
| IP | Options | variable, up to 40 bytes |
| TCP | Options | variable, up to 40 bytes |
| IP | Header checksum | 2 bytes |
| TCP | Checksum | 2 bytes |

These exclusions prevent the classifier from learning deployment-specific
addresses and ports, remove option-length variability, and keep derived
checksum values out of the learning representation. Checksums are not clipped
or perturbed because they are not part of the 1,481 model features.

## 4. Preserve the retained packet structure

Keep the remaining TCP/IP header bytes and TCP segment data in protocol order.
The retained areas have different perturbation policies:

- `ip_header_*`: mutable retained IP-header features;
- `tcp_header_*`: mutable retained TCP-header features; and
- `tcp_segment_data_*`: immutable segment/payload features.

Payload bytes remain classifier inputs. They are not modified by the generator,
which preserves packet functionality and avoids changing encrypted content.

Give each feature a semantic column name that retains its protocol location,
for example:

```text
ip_header_byte_9
tcp_header_byte_14
tcp_segment_data_byte_1
```

Semantic names allow the constraint module to construct mutable and immutable
masks without relying on fragile positional indices.

## 5. Standardize the feature length

Zero-pad the retained representation to exactly 1,481 byte features. Padding
must be added after the real retained content and must not shift protocol-field
positions. Reject or consistently truncate inputs that exceed the supported
maximum before building a dataset; never truncate headers in the middle of a
field.

Every CSV row must have the same feature order. Save that order once and reuse
it across classifier training, generator training, and evaluation.

## 6. Convert and normalize bytes

Convert each retained hexadecimal byte to an integer in `[0, 255]`, then apply:

```text
normalized_byte = integer_byte / 255.0
```

The resulting 1,481 feature values must be numeric, finite, and within `[0, 1]`.
Do not standardize the columns with z-scores: clipping bounds are expressed in
the normalized byte domain.

## 7. Balance and partition the experiment data

Create one binary dataset per attack category by pairing its malicious packets
with an equal number of randomly selected benign packets. Downsample very large
attack categories when necessary to keep experiments computationally balanced.
An optional `AllClasses` dataset can combine equal samples from every attack
category into one malicious class.

Classifier and generator examples must be disjoint. The preferred CSV includes
a `dataset_partition` column with these values:

```text
classifier
generator
```

Within each partition, use five-fold stratified cross-validation. For each fold,
80% of the packets train the model and the held-out 20% is divided equally into
10% validation and 10% testing data. Preserve class proportions during every
split and use the same seed and fold index across training and evaluation.

When `dataset_partition` is absent, the loaders create deterministic disjoint
partitions using `--classifier-fraction` and `--seed`.

## Required CSV schema

Each file must contain:

- exactly 1,481 normalized feature columns;
- `label`, containing only `0` and `1`;
- optional `attack_type`; and
- optional `dataset_partition`.

Example header and rows (abbreviated):

```csv
ip_header_byte_2,ip_header_byte_3,...,tcp_header_byte_15,tcp_segment_data_byte_1,...,label,attack_type,dataset_partition
0.0000,0.1569,...,0.5020,0.1843,...,0,Benign,classifier
0.0000,0.1569,...,0.2509,0.9137,...,1,DoS,generator
```

Example commands using the optional metadata columns:

```bash
python train_classifier.py \
  --data data/cic_ids_2017_packets.csv \
  --partition-col dataset_partition \
  --attack-type-col attack_type \
  --attack-type DoS \
  --fold-index 0

python train_attack.py \
  --data data/cic_ids_2017_packets.csv \
  --partition-col dataset_partition \
  --attack-type-col attack_type \
  --attack-type DoS \
  --classifier-path checkpoints/dos_classifier.pth \
  --fold-index 0
```

## Validation checklist

Before training, verify that:

- only forward TCP packets are present;
- packet labels match the documented endpoints and time windows;
- excluded fields and checksums are absent;
- each row has exactly 1,481 features in identical order;
- every feature lies in `[0, 1]`;
- payload columns use an immutable prefix;
- benign and malicious class counts are recorded;
- classifier and generator partitions share no packet identifiers; and
- duplicate packets do not cross train, validation, and test boundaries.
